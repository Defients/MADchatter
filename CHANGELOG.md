# Changelog

All notable changes to MADchatter are documented here. Dates are in YYYY-MM-DD format.

## [1.0.1] — 2026-09-12

### Added — Local AI / Ollama Realtime Orchestration Overhaul
- **AI Request Scheduler** (`src/lib/aiScheduler.ts`) — Centralized orchestrator with priority-based scheduling, real AbortController cancellation, preemption, telemetry, and typed error taxonomy. Replaces the passive `withAiTimeout` wrapper that rejected callers but left underlying GPU inference running.
- **Priority system** — `critical` (manual Forge) > `interactive` (refine/vision/briefing) > `autonomous` (AutoForge/Smart Replies) > `background` (AutoMemory). Manual Forge preempts background Ollama work instead of queueing behind it.
- **Real cancellation** — All AI calls now pass `AbortSignal` to the provider SDK (OpenAI `signal`, Anthropic `signal`, Gemini `abortSignal`). Timeout = `abortController.abort()`, which terminates the HTTP request and (for Ollama) the underlying generation. No more zombie GPU jobs after timeout.
- **Ollama single-slot serialization** — Local Ollama uses one active inference slot with priority-based preemption. Cloud providers (Gemini/OpenAI/Claude/OpenRouter) remain concurrent — no artificial serialization.
- **Ollama reasoning control** — `buildProviderRequestOptions()` explicitly sets `reasoning_effort: "none"` for all Ollama requests, preventing thinking-capable models from wasting GPU cycles on hidden deliberation. Cloud providers do NOT receive this field.
- **Operation-aware token budgets** — `getOperationTokenBudget()` scales Forge output with requested card count; AutoMemory/vision/refine/autoforge-decide each get bounded budgets. Fixes unbounded `max_tokens` on OpenAI/Gemini branches for autoforgeDecide and extractMemories.
- **Operation-aware timeouts** — `getOperationTimeout()` gives Forge 60s (user waiting), AutoMemory 25s (background, yields faster), Smart Reply 15s, etc.
- **Typed error taxonomy** — `AIRequestTimeoutError`, `AIRequestPreemptedError`, `AIRequestCancelledError`. Intentional preemption is NOT reported as provider failure (`isSchedulerCancellation()` guard in `autoforgeDecide` fallback loop).
- **AutoMemory hardening** — Extraction cursor/watermark prevents reprocessing the same chat window. Minimum-new-information threshold (5 new messages). Exponential backoff after real failures (30s → 60s → 120s → 300s). Preemption does NOT trigger backoff. Stale channel guard discards results if the user switches streamers mid-extraction.
- **Stale-result protection** — AutoForge full_forge captures channel before async generation and discards results if the user switches streamers. Same guard in `useAutoForgeBot.ts`.
- **Provider switch invalidation** — `setActiveProvider()` cancels all active AI requests for the old provider.
- **Ollama health check** (`src/lib/ollamaHealth.ts`) — Lightweight `/v1/models` endpoint check with 30s cache. Distinguishes: configured, connecting, ready, model_unavailable, endpoint_unreachable.
- **Scheduler telemetry** — `[AIQueue]` logs for enqueue/start/complete/timeout/preempt/fail. `getMetricsSummary()` and `getMetricsHistory()` for diagnostics.
- **Scheduler test suite** (`src/lib/aiScheduler.test.ts`) — 31 deterministic tests covering: basic execution, timeout cancellation, preemption, cloud concurrency, Ollama serialization, dedup, provider switch cancellation, slot release, reasoning control, token budgets, timeouts. Run with `npx tsx src/lib/aiScheduler.test.ts`.
- **Ollama default model** — Updated from `llama3.1:8b` to `qwen3.5:9b` (recommended) in `openAiCompatEndpoint()`. Users with custom models are not affected.

### Added — AutoForge Cost & Coordination Improvements
- **Vibe check pre-filter** (`vibeCheck()` in `autoForgeCore.ts`) — Cheap local heuristic run before the expensive `autoforgeDecide` AI call. Skips dead-chat, offline-stream, and user-forging cycles entirely without spending tokens or GPU cycles. Never skips mentions or activity spikes (highest-priority signals). Re-check intervals: 15s (user forging), 30s (dead chat), 120s (offline). Integrated in both `useAutoForge` and `useAutoForgeBot`.
- **Coordinator mention priority** (`botCoordinator.ts`) — `BotCandidate` now carries `isMentioned`. The speaker-floor bidding adds a 0.15 bonus to mentioned bots so they win the floor over slightly-higher-confidence non-mentioned competitors. A mentioned bot with 0.5 confidence beats a non-mentioned bot with 0.64, but loses to one with 0.66+. Calibrated so mentions matter without overriding strong confidence gaps.
- **Jaccard semantic dedup** (`isNearDuplicate()` in `antiRepetition.ts`) — `isDuplicateMessage` now checks Jaccard word-set similarity (default threshold 0.6) in addition to exact match. Catches reworded duplicates (same words, different order) that exact-match misses. Short messages (< 3 words) are excluded to avoid false positives. Propagates to both AutoForge loops via the shared `autoForgeCore` import.
- **Adaptive check-interval backoff** (`computeAdaptiveBackoff()` in `autoForgeCore.ts`) — When AutoForge repeatedly chooses silence during dead periods, the check interval progressively lengthens (×1.5 at 3-5 silences, ×2 at 6-10, ×3 at 10+, capped at 5 min). Resets to base on any non-silence action. Mentions and spikes bypass backoff entirely. Reduces unnecessary AI calls during quiet stretches. Integrated in both hooks with a `consecutiveSilenceRef`.

### Fixed
- **Multi-bot toggle data loss** — Disabling MULTI-BOT no longer erases the bot roster. `disableMultiBot()` previously set `bots: []`, `activeBotId: null`, `manualSendBotId: null`, destroying all configured bots. Now it only flips `multiBotEnabled`; the roster persists via `partialize`. `enableMultiBot()` detects a saved roster and restores it (refreshing the primary bot from global single-bot state) instead of always reseeding a single fresh primary. `exportSettings` now exports bots whenever they exist (sessions still stripped), not only while enabled.
- **Smart Reply send tracking** — Smart replies (keyboard 1/2/3 and click) now record in the sent log, session stats, and event log. Previously they were sent but untracked, breaking anti-repetition and analytics.
- **R34L trailing cringe** — Removed `lol`, `tbh`, `ngl`, `lmao`, `fr`, `lowkey`, `highkey`, `istg`, `frfr` from the chat-style slang lexicon and `trailing "lol"`/`trailing "lmao"`/`xd` from punctuation signals. These were re-encouraging the forced closers the R34L prompt explicitly bans. Added anti-cringe caveat to the formatChatStyleProfile mirror instruction.
- **Profile name capitalization (schema v17)** — Normalized default profile IDs from lowercase (`hype`/`analyst`/`gremlin`) to capitalized (`Hype`/`Analyst`/`Gremlin`) to match the canonical TuningDeck and MultiBotPanel profile IDs. Added a v17 migration that rewrites persisted `primaryProfile`/`activeProfiles` for both the legacy singleton config and each bot's persona config. Older defaults used lowercase; the UI expected capitalized, causing profile selection to silently fail on upgraded installs.
- **Outdated per-bot parity comment** — `useAutoForgeBot.ts` header claimed rule engine, smart replies, post-send engagement, and session goals were "deferred for per-bot mode." All are now implemented; comment updated to reflect reality.
